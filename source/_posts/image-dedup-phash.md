需求是下载某个画师在动态里发布的所有原画，并且**去重——重复的和相似的都不要**。

MD5 去重看起来就够了，但实际跑起来发现：**画师会把同一张画「微调后重发」**，MD5 完全不同，视觉上却几乎是同一张。

这篇记录了怎么用感知哈希（pHash）解决这个问题，以及怎么**校准阈值**。

<!-- more -->

## 数据情况

先爬元数据。1662 条动态，其中带图片的 436 条。

分析图片尺寸时发现一个明显的模式：

```
1     250x250     50 KB    ← 大量重复
1     250x250     50 KB
...
1    1609x2105  1750 KB    ← 真正的画作
1    2480x3508 11299 KB
```

那些 **250×250、51,459 字节** 的图片，MD5 **完全一致**：

```
_probe/small_0.jpg  51459  d58956131caf6e59e70ed9a8f4a0c040
_probe/small_1.jpg  51459  d58956131caf6e59e70ed9a8f4a0c040   ← 同一个文件
```

原来这是 B 站给「表情包」用的占位图，226 处用的是同一个文件。**用 MD5 就能干净地过滤掉。**

## 但 MD5 解决不了这个

真正的问题在画作本身。画师经常这样发动态：

> 「改了一版，调整了不少地方（然后又改了一版，索性都发出来好了」

这三张图：

| 文件 | 尺寸 | 说明 |
|---|---|---|
| `day95 若叶睦.jpg` | 2550×1381 | 原图 |
| `改了一版_1.jpg` | 3824×2072 | 第一次修改 |
| `改了一版_2.jpg` | 3824×2072 | 第二次修改 |

**MD5 全不同**，但 `day95` 和 `改了一版_1` 其实是**同一张画**（只调了色调/打光）。

## 用感知哈希判断「像不像」

pHash（感知哈希）的原理：把图片缩到 32×32、转灰度、做 DCT 变换、取低频部分的 64 位，得到一串指纹。**视觉相似的图，指纹的汉明距离很小。**

```python
import imagehash
from PIL import Image

def phash(path):
    with Image.open(path) as im:
        return imagehash.phash(im.convert("RGB"))

d = phash("a.jpg") - phash("b.jpg")     # 汉明距离
```

## 关键：阈值不能拍脑袋

直接猜「距离小于 10 算重复」是不负责任的。我先**算出全数据集的分布**：

```python
for i, j in itertools.combinations(range(len(files)), 2):
    d = phash(files[i]) - phash(files[j])
    pairs.append((d, files[i], files[j]))
```

结果清晰分成了两群：

```
pHash= 0  Soft & cuddly_1.jpg  <->  Soft & cuddly_2.jpg      ← 同一张
pHash= 0  DAY046_千早爱音.jpg   <->  小改了一点景深和特效.jpg   ← 同一张
pHash= 2  day81 丰川祥子.jpg    <->  祥子这张重新调整...1.jpg   ← 同一张
...
pHash=24  DAY008_墨提斯.jpg     <->  DAY012_若麦.jpg          ← 不同的画
pHash=24  DAY007_睦.jpg        <->  DAY063_若叶睦.jpg        ← 不同的画
pHash=26  DAY032_墨提斯.jpg     <->  DAY037_长崎素世.jpg       ← 不同的画
```

**0–6 是同一张画，10–26 是真正不同的作品。** 中间有明显空隙，阈值取 **8** 有两侧余量。

这就是「用数据定阈值」而不是「凭感觉」的价值。

## 但 pHash 还不够：一个漏网案例

跑完后我检查剩下的最近邻，发现还有一对距离 **10** 的：

```
dist=10  day95 若叶睦.jpg  <->  改了一版_1.jpg
```

刚好卡在阈值之上。**这两张到底是不是同一张？**

pHash 在「大面积改色调」时会漂移较大，所以不能只看它。加一个**归一化结构比对**：

```python
# 缩到同尺寸后逐像素比较
a = np.asarray(Image.open(f1).convert("L").resize((256, 140)), dtype=float)
b = np.asarray(Image.open(f2).convert("L").resize((256, 140)), dtype=float)
changed = 100 * (np.abs(a - b) > 30).mean()     # 差异超过 30 的像素占比
```

结果：

| 对比 | 差异像素 | 判断 |
|---|---|---|
| `day95` ↔ `改了一版_1` | **5.8%** | 同一张（只改了色调） |
| `改了一版_1` ↔ `改了一版_2` | **51.5%** | **不同的画** |
| `day95` ↔ `改了一版_2` | 49.6% | 不同的画 |

**同一张画，归一化后只有 5.8% 的像素明显不同；真正不同的画，差异超过 50%。** 又是一次清晰的分界。

所以最终判重逻辑是**两个条件满足其一**：

```python
def same_artwork(a, b):
    if a.md5 == b.md5:
        return True
    if phash_distance(a, b) <= 8:
        return True
    # 宽高比相近 + 归一化后像素差异小  → 同一张画的轻微改动
    if abs(a.ratio - b.ratio) < 0.02:
        if changed_pct(a, b) <= 15:
            return True
    return False
```

## 又一个坑：保留哪个版本？

判重之后要决定**留哪一张**。我最初的逻辑是「留发布时间最新的」——毕竟修改版通常更完善。

结果删错了：

```
保留: 祥子这张重新调整了一些地方_2.jpg   (1240×1754)
丢弃: day82 若叶睦.jpg                 (2480×3508, 11 MB)
```

**画师重传的是降分辨率的版本！** 原图 2480×3508（11 MB），重传的只有 1240×1754。

修复：**排序时分辨率优先，其次才是时间**。

```python
ranked = sorted(group, key=lambda x: (x.width * x.height, x.pub_ts, x.bytes),
                reverse=True)
```

改完后正确保住了高清原图。

| 阶段 | 数量 |
|---|---|
| 抓取到的候选 | 176 |
| MD5 完全相同 | −2 |
| pHash 相似（≤8） | −13 |
| 归一化结构相同（≤15%） | −2 |
| **最终保留** | **159** |

## 小结

1. **MD5 去重只解决「完全相同」**。真实的重复往往是「相似但不相同」——调色、裁切、重新导出都会改变字节。

2. **pHash 是判断「视觉相似」的好工具**，但**阈值必须用实际数据分布来定**，不要照抄网上的数字。打印出最近邻的距离分布，分界通常很明显。

3. **pHash 有极限**。大范围改色调时会漂移，需要辅以「归一化后逐像素比对」这类结构相似度来判断。

4. **「留哪一张」也要想清楚**。默认按时间取最新可能是错的——本例中画师重传的是**降分辨率**版本，必须按分辨率优先排序。

5. **永远打印中间结果**。如果我直接把 176 张全下载完，就不会发现「相似但不同」这一层；如果不检查剩余最近邻，就不会抓到距离 10 的两个漏网案例。
